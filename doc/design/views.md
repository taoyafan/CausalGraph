# 视图层（Views）

> 视图层是**图对人的导航入口**，与图的连通性解耦。图内部仍是一张全局 DAG；视图只决定
> "该从哪些结论节点看进去、怎么分类"。本文件只记最终结论。

## 1. 为什么需要独立的视图层

- 按 **id 前缀**分组：会把三条互不相干的 `ind.*` 子图混成一类，也无法表达"一个节点服务多个结论"。
- 按 **弱连通分量**分组：产业链最终会把各公司连成一张大图（碳酸锂→…→电池→各公司盈利），
  连通分量会坍缩成一块，公司之间再也分不开。
- 结论：导航**不能**依赖连通性。视图 = 人类命名的**锚点节点 + 分类**，成员由锚点的
  上游闭包自动求得，允许不同视图成员重叠。

## 2. 数据结构：`data/views.json`

```
{ note, categories: [ { name, note?, views: [ { name, anchor, panel?:[ids], note? } ] } ] }
```

- `anchor`：该视图要回答的**结论节点 id**（公司=次年前瞻 PE，产业=环节价格）。必须存在，否则导出报错。
- `panel`：看板并列展示的若干节点 id（公司=三年前瞻 PE；产业=价格+供需/毛利）。缺省时退化为锚点单格。
- 加一家公司/一个环节 = 加一条视图条目，不改代码。

## 3. 成员与诊断桶（`build_views`，只读拓扑、不求值）

- **视图成员** = `锚点的上游祖先闭包 ∪ {锚点}`；panel 各节点的闭包也计入"已覆盖"。
- **诊断桶 orphans** = 不在任何视图覆盖集内的**算子节点**——多为旁支 `vs/ratio` 交叉校验
  节点（它们是锚点的**下游**，不是上游，故不被任何锚点闭包覆盖）。它是给建模者的**覆盖率
  自检**（"哪些算子还没被任何视图收录"），**只在 CLI `outline --orphans` 暴露**，不进面向
  浏览者的 Web——否则会把几十个自检/衍生节点平铺成噪音。
- 锚点/panel 指向不存在的节点 → 收进 `errors`，导出时以 `[WARN]` 打印，倒逼命名/纠错。

## 4. 消费端

- **Web**（`web/index.html`）：下拉按`分类(optgroup) → 视图`；选中视图 = 顶部 panel 看板条 +
  锚点贡献树钻取；第二级下拉列出该视图全部成员（★锚点 → ·算子 → ◦数据源）供跳至任意节点。
  数据来自 `window.CG_EXPORT.views.categories`（由 `cgraph export` 写入）；**诊断桶不进 Web**。
- **CLI**（`cgraph outline`）：默认按`分类 → 视图(★锚点 + 成员计数)`列出，末尾诊断桶计数
  （`--orphans` 展开，**诊断桶只在这里看**）；`--view <名>` 展开单个视图成员；`--raw` 回退到
  旧的纯结构鸟瞰（按图簇的 源/中/终 三层，供调试）。

## 5. 中文命名

- 视图名（`name`）直接写中文，与 `cgraph/webexport.py` 的 `GROUP_LABELS` 无关；
  底层节点 id 仍可用拼音前缀。
