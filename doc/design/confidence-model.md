# 置信度模型（Confidence Model）设计细节

> 对应 [README §2.3 概率与置信度融合机制](../../README.md#23-概率与置信度融合机制)。

## 1. 核心约束：数据节点零依赖

数据节点是原子的：只有 **(原始分布 $p_{raw}$, 置信度 $C$, `Source_ID`)** 三元组，不引用、不依赖图中任何其它节点（包括自己的历史数据、同行业其它公司数据、图中因果上游节点）。

## 2. 单节点置信度展宽公式

$C\in(0,1]$ 直接、单向地展宽该节点自身的分布，公式只用到这个节点自己的字段：

| 分布 | 展宽公式 |
|------|---------|
| Normal($\mu,\sigma$) | $\sigma_{eff} = \sigma / C$ |
| Triangular(min, mode, max) | $\text{new\_min} = \text{mode} - \dfrac{\text{mode}-\text{min}}{C}$，$\text{new\_max} = \text{mode} + \dfrac{\text{max}-\text{mode}}{C}$ |
| Uniform(min, max) | 以中点为中心，两端按 $1/C$ 拉伸 |
| Point / Bernoulli | 展宽半宽 $= k\lvert v\rvert\,(1/C - 1)$（$k$ 取 domain 量级的约 1%）。**$C=1$ 时半宽严格为 0 —— audited 等确定披露值退化为精确点，不凭空造噪声**；$C<1$ 才按缺失的置信度展开为绕 $v$ 的三角分布 |

**Domain 钳制**：每种指标类型注册一个静态物理/常识边界常量（如"价格 ≥ 0""同比增速 ≥ −100%"，随指标类型写入 Schema，不是对其它节点的依赖），展宽后的分布始终按边界截断。$C\to 0$ 时，分布自然收敛到"边界内的均匀分布"——这就是 README 里"退化为行业常识宽分布"的准确含义，不需要额外发明一个"先验节点"。

## 3. 多源数据融合（与展宽是两套独立机制）

同一指标存在多个数据节点（不同 `Source_ID`，如研报 A、研报 B）时，**不通过节点间依赖处理**，而是各自独立展宽后，一起接入下游的**融合算子节点**，由算子按各自 $C$ 加权/混合，产出新的输出节点。**严格禁止单个数据节点引用/合并多个数据源**：一个数据节点只能对应一个 `Source_ID`（假设节点按**一论点一锚**——同向多证据可归一锚，只有反向/交叉验证的分歧才拆节点后由算子融合），多源只能以"多个独立节点 + 融合算子"的形式入图。

融合语义（供算子实现参考）：

- **Mixture（默认）**：$p(x) = w_A p_A(x) + w_B p_B(x)$。两来源分歧大时保留双峰，如实反映"方法/来源冲突"，应触发 `ALERT: Method Conflict`。
- **乘积/贝叶斯融合**：$p(x)\propto p_A(x)p_B(x)$，适合"两来源本该测量同一真值"的场景，重叠小则给出冲突信号。
- 避免直接加权平均成一个点估计——会制造 README 明确摒弃的"伪精确"。

## 4. 概率传导引擎（解析 vs 蒙特卡洛）

默认**解析融合**：线性/正态场景用精确闭式；非线性算子用矩传播（Delta 方法）近似均值方差。当出现以下情况时降级为**蒙特卡洛**：

- 节点间存在显式相关性（可用共享随机数自然带入相关性，无需协方差矩阵）；
- 强非线性 + 大方差，矩传播误差不可接受；
- 需要保留多峰/尾部形状（如 Mixture 未坍缩的场景）。

## 5. 置信度分级规范：类型与数值解耦

为避免不同来源/不同 Agent 自由心证填小数，$C$ 的赋值拆成两层，跨节点也能可比：

- **证据类型 `evidence_type`（AI 判定，固定枚举，语义稳定不变）**：

  | `evidence_type` | 说明 | 例子 |
  |---|---|---|
  | `audited` | 审计/官方披露的确定数字 | 财报科目、交易所公告 |
  | `guidance` | 公司一手指引 | 业绩指引、招股书 |
  | `analyst_estimate` | 研报测算 | 主流券商研报结论 |
  | `extrapolation` | 外推：基于历史数据的机械统计外推，可复现、无主观判断 | 历史价格线性外推、时间序列模型外推 |
  | `inference` | 推断/假设：依赖分析师主观逻辑判断的推断，非机械统计 | 同类商品定价类比、逻辑假设推导 |
  | `rumor_or_missing` | 传闻/缺项自动填充 | 媒体传闻、无法验证消息、高熵缺省节点 |

- **`type → C` 查表（独立维护，可单独调参）**：

  | `evidence_type` | 当前 $C$ |
  |---|---|
  | `audited` | 1.0 |
  | `guidance` | 0.8 |
  | `analyst_estimate` | 0.6 |
  | `extrapolation` | 0.45 |
  | `inference` | 0.3 |
  | `rumor_or_missing` | 0.2 |

**实时查表，不在节点里烤死 C 数值**：数据节点只存 `evidence_type`，不存 $C$ 数值。每次计算（展宽/融合）时用当前的查表结果取 $C$。改表（比如回测发现 `analyst_estimate` 该从 0.6 调到 0.5）后，重新跑一遍图计算即可，**所有节点的结果自动跟着变准**，不需要改任何一条已入图数据。暂不引入版本号/生效时间等审计机制——按敏捷/第一性原理，这类复杂度等真的需要追溯"某次结果用的哪版表"时再加。
