# 覆盖式演绎会话（Overlay What-if）设计

> 状态：需求与架构已定，显示方案讨论中（见 §6）。本文只记录已决策内容。

## 1. 定位

投资沙盘的核心体验：用户在既有图上**临时替换若干假设值，看最终预测如何变化**。
不是压力测试，而是用户自定义情景："我觉得某个假设应该处于某个区间时，结果是什么"。

- 改动由 AI 执行（用户对话式提出，AI 改图），用户不做滑块/表单操作。
- 覆盖是**临时的、可叠加、可撤销**的；原有数据永不丢失、不修改，只是本次演绎不参与计算。

## 2. 架构：覆盖层（Overlay）

- 一个**演绎会话（scenario session）**持有一张 `{节点id → 临时分布}` 映射表。
- 引擎求值加可选 overrides 参数：`_eval` 解析到某节点时，覆盖层命中则按临时分布
  采样，否则走原节点。原节点的分布/来源/置信度原地保留，仅被本次求值旁路。
- 求值沿下游拓扑传播：只重算被覆盖节点的下游子图（与 E13 响应式引擎同机制）。

## 3. 诚实性约束（README 数据诚实性原则的延伸）

- 覆盖值是一种新的证据类型（`user_override`），记录：谁、何时、覆盖了哪个节点、
  理由是什么。溯源链不断，杜绝"演着演着分不清哪个数是真的"。
- 被覆盖节点在一切输出中必须显式可辨（CLI 标记 / 端上高亮），不允许与基线值混淆。

## 4. 基线与情景对比

- 基线与情景是**同一张图的两次求值**，对比免费：终值差异、下游节点 diff
  直接对两组 stats 做 diff。
- 多条情景可并存（A/B 比较）；清除某个覆盖即恢复原值并自动重算。

## 5. CLI 语义（拟定）

```
cgraph scenario new <name>            # 开演绎会话
cgraph scenario set <node> <dist>     # 覆盖某假设节点（记录 user_override）
cgraph scenario diff [<node>]         # 基线 vs 情景：终值变化 + 下游传导 diff
cgraph scenario drop <node> | clear   # 撤销某覆盖 / 清空会话
```
