## 设计哲学（Design Philosophy）

> 贯穿全部架构决策的核心原则：**AI 生成的东西必须简单、可审计；计算与易变的部分一律交给程序，不经过 AI 之手。**

- AI（Parsing/推断）只允许输出**简单、可枚举、可审计**的内容：证据类型标签、算子选择、分布参数——不允许自由生成脚本、公式或数值换算逻辑。
- 一切**计算**（分布展宽、概率传导、算子求值）和一切**容易变化**的东西（置信度数值、先验参数）都由**程序**（固定库 + 查表）执行/维护，不由 AI 直接产出。
- 具体体现：
  - 算子库 / 概率分布库固定，AI 只能挑选并填参数，不能编写脚本（见 2.2）。
  - 置信度 $C$：AI 只判定"证据类型"，具体数值由程序查表得到，AI 不直接给数字（见 2.3）。

## 2. 架构方案（CausalGraph 架构）

### 2.1 基础模型：纯 Node + Edge 与数据源解耦

- **极简图模型**：放弃复杂插件系统，将数据、逻辑、算子、突发事件全部抽象为 **Node（节点）**，连线 **Edge（有向边）** 仅代表数据与事件的传导方向。
- **数据源独立**：数据源仅生成属于自己的独占数据节点（带 `Source_ID`），不直接改写图上现有节点。不同数据源对同一指标的碰撞，由后置的**算子节点（Function Node）**进行加权与融合。

### 2.2 双重约束：固定算子库 + 固定概率分布库

- **算子库约束**：AI Parsing 不得自由编写任意脚本，只能从预设的标准算子库（如弹性算子、成本加成算子等）中挑选并填充参数。
- **概率分布库约束**：固定为 4 种标准分布：

  | 分布 | 名称 | 参数语义 |
  |------|------|----------|
  | `Uniform` | 均匀分布 | 上下界 |
  | `Triangular` | 三角分布 | 最悲观 / 最可能 / 最乐观 |
  | `Normal` | 正态分布 | 均值 / 标准差 |
  | `Point / Bernoulli` | 单点 / 伯努利分布 | 确定值 / 二元概率 |

### 2.3 概率与置信度融合机制

**节点二元属性：**

- **数据节点**：承载概率分布（数值波动）与数据源置信度 $C_{data}$。**数据节点原子化、单一来源、零依赖**——只由自己的 (分布, $C$) 两个字段决定，不引用图中任何其它节点。
- **算子节点**：纯数学算子不打折（$C_{op} = 1.0$）；主观推断/假设算子按逻辑把握度打折传递（$C_{op} < 1.0$）。

**单节点置信度展宽**：$C$ 直接对数据节点自身分布做 $1/C$ 展宽（不依赖任何其它节点）：

- Normal：$\sigma_{eff} = \sigma_{raw} / C$。
- Triangular / Uniform：以众数（或中点）为中心，两侧边界按 $1/C$ 拉伸。
- Point/Bernoulli：先退化为一个极小种子宽度的 Normal/Triangular，再套用上述展宽（否则 0 宽度乘以任何倍数仍是 0）。

每种指标类型注册一个静态的**物理/常识边界**（如价格 ≥ 0），展宽结果始终按此边界截断，防止 $C\to 0$ 时退化出不合理的值；这就是"退化为行业常识宽分布"的自然极限，不需要额外节点。

**多源数据融合**：与单节点展宽是两套独立机制——同一指标的多个数据节点（不同 `Source_ID`）由下游的**融合算子节点**加权/混合，产出新的输出节点（见 2.1）。

**置信度分级规范**：$C$ 不由 AI 自由填写数值，而是 AI 只判定一个固定的"证据类型"（如审计数据/公司指引/研报测算/历史外推/主观推断/传闻），具体 $C$ 数值由独立维护的查表得到，方便后续回测校准时整体调整而不需改历史数据。

**缺项处理**：完全缺失数据源时，只有系统自动生成的高熵宽分布 + 低置信度（如 $0.2$）数据节点参与计算，引发下游不确定性膨胀。

> 完整推导、公式来源与示例见 [doc/design/confidence-model.md](doc/design/confidence-model.md)。

### 2.4 层级解包与响应式风控引擎

- **增量构建与全局图缓存**：全局图与各节点样本**持久化缓存**，与“加节点”解耦——新增/变更数据源时只**扫描增量节点并入全局图**、只重算受影响的下游子图，查询直接**读缓存**，避免每次全量重建重算（现状为每次命令全量重扫重算，见 [doc/design/architecture.md](doc/design/architecture.md)）。
- **Baseline + Delta 层级结构**：采用 `新总值 = 基线 + Delta` 算子叠加微观事件，解决宏微观层级打架问题。
- **下游脏标记与变化阻断**：更新发生时沿着 Downstream 拓扑路径进行 Dirty Marking；若算子计算输出无明显变化，触发 **Short-circuiting（变化阻断）** 终止后续计算。
- **自动化风控链路**：下游概率方差剧烈膨胀或数值离群时 → 阻断传导 → AI 自审 → 上报管理员待办 → 生成定向 AI 补全 Task。

### 2.5 CLI 交互层（Text-based DSL Engine）

- **字符树 + 管道符**：输出以 `Focus_Node_ID` 为中心的 `[UPSTREAM] → [FOCUS] → [DOWNSTREAM]` 局部子图。
- **语义显式化**：用 `()` 标记数据节点，用 `[]` 标记算子节点，末尾直接追加 `ALERT` 标记（如 `ALERT: High Variance`），方便 AI Agent 直观抓取风险。
- **多档输出（`focus` 命令，`--level` 一档搞定）**：
  - `--level 0` 一行摘要：FOCUS 分位数 + 假设节点计数/最低 C + 告警；
  - `--level 1` 一层上游：FOCUS + 直接上游，每行带节点 id；
  - `--level 2` 全树：每行带节点 id（可直接 `trace`），共享节点去重（↺ 已展开），确定性子树折叠（⟂，全 Point(C=1)+C_op=1 分支）；
  - `--level 3`（默认）公式视图：按算子模板渲染中缀表达式看整个演算过程，数据节点内联 `[值]`（只带值不带区间，C 由 `?` 标记与假设清单体现），假设节点带 `?` 标记，末尾附假设清单。
  - `--seed` 默认不固定（每次运行重采样）；需要可复现时显式传 `--seed 42`。

### 2.6 Agent 团队与跨 Harness 分工

建图由一支**分工明确的 Agent 团队**协作完成，用"提取/审核分离、数据/算子分离"把可审计性落到组织结构上：

- **主 Agent（= 对话/默认 Agent）** 拆解目标、分发搜索任务、汇总并触发求值——**就是当前与你对话的默认 Agent，职责写在 [AGENTS.md](AGENTS.md)，无独立 agent 文件**；
- **Scout（搜索提取）** 检索来源、把原子事实提取为数据节点（零计算）；
- **Reviewer（审核）** 对新建节点/新算子行使否决权（证据类型诚实、出处齐全、数据零计算、不成环）；
- **Operator Author（算子作者）** 在"没有合适算子"时把运算实现为受控代码入库，而非内联公式。

其中 Scout / Reviewer / Operator Author 三个专家角色落为 `.github/agents/*.agent.md` 子 Agent（需上下文隔离 + 工具收窄）。
每个角色的**规范化提示词、问题→解决方案手册、跨 harness 适配约定**见
[doc/design/agent-teams.md](doc/design/agent-teams.md)——该文是唯一事实源，各 harness 只做适配层。

## 3. Use Cases

> 用真实产业链场景验证“数据接入 → 算子推演 → 概率传导 → CLI 呈现”的完整闭环。

### 3.1 新宙邦 2026 全年归母净利润预测

**目标**：预测新宙邦（Capchem）2026 全年归母净利润的概率区间，用两条独立路径交叉验证，
并可回溯每个假设的数据源与置信度。

**计算图（两条独立路径 + Mixture 融合，全部为真实数据）：**

```text
Path A（bottom-up，半年报锚定）              Path B（top-down，券商一致预期）
──────────────────────────────              ──────────────────────────────
(H1_已实现 9.838亿, audited) ──┐            (开源 22.2) (光大 21.9) (华源 24.1) ...
(H2_季度环比外推, extrapolation)┼[求和]      共 12 家券商 2026E ──┐
                               │            (中原 18.2) ─────────┼[Mixture]→(全年_topdown)
                               ▼                                  │
                (全年_bottomup) ──────────[Mixture 融合]──────────┘
                                              │
                                              ▼
                         [FOCUS] (归母净利润_2026_全年)  ALERT: Method Conflict（若分歧过大）
```

- **Path A（bottom-up）**：H1 用 2026 半年报已实现值 9.838 亿元（`audited`，$C=1.0$）；
  H2 由 Q1/Q2 实际季度环比外推（`extrapolation`，$C=0.45$）为三角分布，相加得全年。
- **Path B（top-down）**：10 家券商 2026E 预测（`analyst_estimate`，C=0.6），来自同花顺 F10
  盈利预测页（检索 2026-08-29）：
  华安 21.00 / 长城 21.36 / 国海 21.64 / 光大 21.92 / 开源 22.18 / 国联民生 22.25 /
  东吴 22.33 / 华泰 23.45 / 西部 24.12 / 华源 24.15（亿元，`data/sources/capchem_broker_forecasts_2026.json`），
  用 Mixture 等权融合为一致预期节点 `capchem.profit.fy2026e.consensus`（`data/operators/capchem_broker_consensus_2026.json`）。
- **最终融合**：Path A 与 Path B 是同一目标（全年净利润）的两种独立估计，用 Mixture 融合；
  分歧过大则触发 `ALERT: Method Conflict`（对应 doc/design/confidence-model.md §3 的融合语义）。

**可运行实现**：全局单图——数据节点独立存于 [data/sources/](data/sources)（含 `source_url` / `retrieved_at` / `publisher` 出处字段），
算子子图见 [data/operators/](data/operators)（`inputs` 即边，可跨子图引用任意上游节点 id）；
引擎为 [cgraph/](cgraph) 包，结构说明见 [doc/design/architecture.md](doc/design/architecture.md)。
没有「每个 use case 一个图文件」——"use case" 就是指定一个 focus 节点 id：

```powershell
python -m cgraph.cli focus capchem.profit.fy2026
# 券商一致预期（top-down 路径）：
python -m cgraph.cli focus capchem.profit.fy2026e.consensus
# 溯源某数据节点来源：
python -m cgraph.cli trace capchem.profit.h1_2026
```

真实运行输出（截断，检索日 2026-08-27）：

```text
FOCUS = capchem.profit.fy2026  ->  P10=19.50 P50=20.97 P90=22.48  (mean=21.05)

[mixture] (归母净利润_2026全年) P10=19.50 P50=20.97 P90=22.48 亿元
├─ [sum] (..._自下而上(H1实际+H2外推)) P10=19.51 P50=20.85 P90=22.46 亿元
│  ├─ (归母净利润_2026H1(已实现)) ~ Point(9.838) C=1.00[audited]
│  └─ (归母净利润_2026H2(季度环比外推)) ~ Tri(9.8/10.8/12.2) C=0.45[extrapolation]
└─ [mixture] (..._自上而下(12家券商一致预期)) P10=19.50 P50=21.23 P90=22.49 亿元  ⚠ Method Conflict (27.8% > 15%)
```

两路独立估计高度一致（bottom-up P50 20.85 vs 券商一致预期 P50 21.23），互相印证；
而券商内部因华源(24.1)与中原(18.2)分歧较大，Path B 触发 Method Conflict 告警。

> **待补充**：Path A 的 H2 外推应接入完整的量价成本算子链（而非直接给区间）；分业务净利拆分需解析半年报 PDF 正文；与历史实际值的回测校准。

### 3.2 新宙邦 2027 / 2028 年净利润预测（多期外推）

**目标**：在 3.1 的单期图基础上，向后外推 2027 / 2028 年度归母净利润；重点是**随年份远去、不确定性逐年放大**，并显式拆出驱动因子。

**建模要点（相对 3.1 的增量）：**

- **时间展开**：将“年份”作为显式维度，每年一个 `(归母净利润_YYYY)` 节点；后一年以前一年为基线（Baseline + Delta）。
- **驱动因子拆解**：产能投放节奏、出货量 CAGR、均价下行斜率（电解液降价趋势）、新业务（钠电/半导体氟化学品）的放量期权。
- **不确定性逐年放大**：越远的年份，驱动因子的分布方差更大、推断算子的 $C_{op}$ 更低，叠加后 2028 年的置信度显著低于 2027 年。

**驱动因子节点（示例）：**

| 节点 | 分布类型 | 参数 | 数据源 | 置信度 $C$ |
|------|----------|------|--------|-----------|
| `(出货量_CAGR_26→28)` | Triangular | 悲观/可能/乐观（%） | 多家研报均值 | 0.5 |
| `(电解液均价年降幅)` | Normal | 均值/标准差（%/年） | 行业供需模型 | 0.4 |
| `(新业务放量_28)` | Triangular | 悲观/可能/乐观（亿元） | 公司规划 + 推断 | 0.3 |

**算子节点（示例）：**

| 算子 | 类型 | $C_{op}$ | 说明 |
|------|------|----------|------|
| `[复利外推算子]` | 推断算子 | 0.6 | 次年基线 = 本年值 × (1 + CAGR) |
| `[均价衰减算子]` | 推断算子 | 0.5 | 逐年施加降价斜率 |
| `[新业务叠加算子]` | Delta 算子 | 0.4 | 在基线上叠加新业务毛利 |

**预期 CLI 输出（示意）：**

```text
cgraph focus 归母净利润_2028 --chain year

(归母净利润_26H2) → (归母净利润_2026) [复利外推] C=0.55
        │
        ▼
(归母净利润_2027) ~ Triangular(P10=.., P50=.., P90=..)  C=0.42
        │   ALERT: Widening Variance
        ▼
(归母净利润_2028) ~ Triangular(P10=.., P50=.., P90=..)  C=0.30
            ALERT: Low Confidence (远期外推 + 新业务放量不确定)
```

> **设计价值**：验证“不确定性随预测期限自然膨胀”，而不是靠人工拍一个单点数字。

### 3.3 新宙邦当前目标价估算

**目标**：把 3.1 / 3.2 的利润预测终端到**目标价（概率区间）**，给出 P10 / P50 / P90 三档估值而非单一目标价。

**估值链（简化）：**

```text
(归母净利润_2027) ─[EPS 算子]─→ (EPS_2027) ─┐
                                              ├─[PE 估值算子]─→ (目标价) ─[安全边际算子]─→ (买入区间)
(给定 PE 区间)   ────────────────────────────┘
```

**输入节点（示例）：**

| 节点 | 分布类型 | 参数 | 数据源 | 置信度 $C$ |
|------|----------|------|--------|-----------|
| `(总股本)` | Point | 确定值（亿股） | 定期报 | 1.0 |
| `(给定_PE_2027)` | Triangular | 悲观/可能/乐观（倍） | 可比公司 + 历史中枢 | 0.5 |
| `(安全边际折扣)` | Uniform | 下下限（%） | 风控策略 | 0.8 |

**算子节点（示例）：**

| 算子 | 类型 | $C_{op}$ | 说明 |
|------|------|----------|------|
| `[EPS 算子]` | 数学算子 | 1.0 | EPS = 归母净利润 / 总股本 |
| `[PE 估值算子]` | 数学算子 | 1.0 | 目标价 = EPS × PE |
| `[安全边际算子]` | 推断算子 | 0.8 | 买入区间 = 目标价 × (1 − 折扣) |

**预期 CLI 输出（示意）：**

```text
cgraph focus 目标价 --depth 2

[UPSTREAM]
  (EPS_2027)      ~ Triangular(...)   C=0.42
  (给定_PE_2027)  ~ Triangular(...)   C=0.5
        │
        ▼
[FOCUS] (目标价) ~ Triangular(P10=.. 元, P50=.. 元, P90=.. 元)  C=0.45
        │
        ▼
[DOWNSTREAM]
  (买入区间)   ~ [低于 P50 安全边际价]   ALERT: Wide Range (PE 与盈利双重不确定)
```

> **要点**：目标价的不确定性 = 盈利预测不确定性 × 估值（PE）不确定性，两重区间叠加，天然适合用概率区间而非单点表达。
