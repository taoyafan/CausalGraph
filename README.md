## 设计哲学（Design Philosophy）

> 贯穿全部架构决策的核心原则：**AI 生成的东西必须简单、可审计；计算与易变的部分一律交给程序，不经过 AI 之手。**

- AI（Parsing/推断）只允许输出**简单、可枚举、可审计**的内容：证据类型标签、算子选择、分布参数——不允许自由生成脚本、公式或数值换算逻辑。
- 一切**计算**（分布展宽、概率传导、算子求值）和一切**容易变化**的东西（置信度数值、先验参数）都由**程序**（固定库 + 查表）执行/维护，不由 AI 直接产出。
- 具体体现：
  - 算子库 / 概率分布库固定，AI 只能挑选并填参数，不能编写脚本（见 2.2）。
  - 置信度 $C$：AI 只判定"证据类型"，具体数值由程序查表得到，AI 不直接给数字（见 2.3）。

## 2. 架构方案（CausalGraph 架构）

### 2.1 基础模型：纯 Node + Edge 与数据源解耦

- **极简图模型**：放弃复杂插件系统，将数据、逻辑、算子、突发事件全部抽象为 **Node（节点）**，连线 **Edge（有向边）** 仅代表数据与事件的传导方向。
- **数据源独立**：数据源仅生成属于自己的独占数据节点（带 `Source_ID`），不直接改写图上现有节点。**严格单一来源：一个节点只能对应一个数据源/一条证据，禁止单个节点引用/合并多个数据源**（数据节点与假设节点一视同仁——假设节点一条证据一个节点，多证据拆节点由下游算子汇总）；不同数据源对同一指标的碰撞，必须各建独立数据节点，由后置的**算子节点（Function Node）**进行加权与融合。

### 2.2 双重约束：固定算子库 + 固定概率分布库

- **算子库约束**：AI Parsing 不得自由编写任意脚本，只能从预设的标准算子库（如弹性算子、成本加成算子等）中挑选并填充参数。
- **概率分布库约束**：固定为 4 种标准分布：

  | 分布 | 名称 | 参数语义 |
  |------|------|----------|
  | `Uniform` | 均匀分布 | 上下界 |
  | `Triangular` | 三角分布 | 最悲观 / 最可能 / 最乐观 |
  | `Normal` | 正态分布 | 均值 / 标准差 |
  | `Point / Bernoulli` | 单点 / 伯努利分布 | 确定值 / 二元概率 |

### 2.3 概率与置信度融合机制

**节点二元属性：**

- **数据节点**：承载概率分布（数值波动）与数据源置信度 $C_{data}$。**数据节点原子化、单一来源、零依赖**——只由自己的 (分布, $C$) 两个字段决定，不引用图中任何其它节点。
- **算子节点**：纯数学算子不打折（$C_{op} = 1.0$）；主观推断/假设算子按逻辑把握度打折传递（$C_{op} < 1.0$）。

**单节点置信度展宽**：$C$ 直接对数据节点自身分布做 $1/C$ 展宽（不依赖任何其它节点）：

- Normal：$\sigma_{eff} = \sigma_{raw} / C$。
- Triangular / Uniform：以众数（或中点）为中心，两侧边界按 $1/C$ 拉伸。
- Point/Bernoulli：先退化为一个极小种子宽度的 Normal/Triangular，再套用上述展宽（否则 0 宽度乘以任何倍数仍是 0）。

每种指标类型注册一个静态的**物理/常识边界**（如价格 ≥ 0），展宽结果始终按此边界截断，防止 $C\to 0$ 时退化出不合理的值；这就是"退化为行业常识宽分布"的自然极限，不需要额外节点。

**多源数据融合**：与单节点展宽是两套独立机制——同一指标的多个数据节点（不同 `Source_ID`）由下游的**融合算子节点**加权/混合，产出新的输出节点（见 2.1）。

**置信度分级规范**：$C$ 不由 AI 自由填写数值，而是 AI 只判定一个固定的"证据类型"（如审计数据/公司指引/研报测算/历史外推/主观推断/传闻），具体 $C$ 数值由独立维护的查表得到，方便后续回测校准时整体调整而不需改历史数据。

**缺项处理**：完全缺失数据源时，只有系统自动生成的高熵宽分布 + 低置信度（如 $0.2$）数据节点参与计算，引发下游不确定性膨胀。

> 完整推导、公式来源与示例见 [doc/design/confidence-model.md](doc/design/confidence-model.md)。

### 2.4 层级解包与响应式风控引擎

- **增量构建与全局图缓存**：全局图与各节点样本**持久化缓存**，与“加节点”解耦——新增/变更数据源时只**扫描增量节点并入全局图**、只重算受影响的下游子图，查询直接**读缓存**，避免每次全量重建重算（现状为每次命令全量重扫重算，见 [doc/design/architecture.md](doc/design/architecture.md)）。
- **Baseline + Delta 层级结构**：采用 `新总值 = 基线 + Delta` 算子叠加微观事件，解决宏微观层级打架问题。
- **下游脏标记与变化阻断**：更新发生时沿着 Downstream 拓扑路径进行 Dirty Marking；若算子计算输出无明显变化，触发 **Short-circuiting（变化阻断）** 终止后续计算。
- **自动化风控链路**：下游概率方差剧烈膨胀或数值离群时 → 阻断传导 → AI 自审 → 上报管理员待办 → 生成定向 AI 补全 Task。

### 2.5 CLI 交互层（Text-based DSL Engine）

- **字符树 + 管道符**：输出以 `Focus_Node_ID` 为中心的 `[UPSTREAM] → [FOCUS] → [DOWNSTREAM]` 局部子图。
- **语义显式化**：用 `()` 标记数据节点，用 `[]` 标记算子节点，末尾直接追加 `ALERT` 标记（如 `ALERT: High Variance`），方便 AI Agent 直观抓取风险。
- **多档输出（`focus` 命令，`--level` 一档搞定）**：
  - `--level 0` 一行摘要：FOCUS 分位数 + 假设节点计数/最低 C + 告警；
  - `--level 1` 一层上游：FOCUS + 直接上游，每行带节点 id；
  - `--level 2` 全树：每行带节点 id（可直接 `trace`），共享节点去重（↺ 已展开），确定性子树折叠（⟂，全 Point(C=1)+C_op=1 分支）；
  - `--level 3`（默认）公式视图：按算子模板渲染中缀表达式看整个演算过程，数据节点内联 `[值]`（只带值不带区间，C 由 `?` 标记与假设清单体现），假设节点带 `?` 标记，末尾附假设清单。
  - `--seed` 默认不固定（每次运行重采样）；需要可复现时显式传 `--seed 42`。

### 2.6 Agent 团队与跨 Harness 分工

建图由一支**分工明确的 Agent 团队**协作完成，用"提取/审核分离、数据/算子分离"把可审计性落到组织结构上：

- **主 Agent（= 对话/默认 Agent）** 拆解目标、分发搜索任务、汇总并触发求值——**就是当前与你对话的默认 Agent，职责写在 [AGENTS.md](AGENTS.md)，无独立 agent 文件**；
- **Scout（搜索提取）** 检索来源、把原子事实提取为数据节点（零计算）；
- **Reviewer（审核）** 对新建节点/新算子行使否决权（证据类型诚实、出处齐全、数据零计算、严格单一来源、不成环）；
- **Operator Author（算子作者）** 在"没有合适算子"时把运算实现为受控代码入库，而非内联公式。

其中 Scout / Reviewer / Operator Author 三个专家角色落为 `.github/agents/*.agent.md` 子 Agent（需上下文隔离 + 工具收窄）。
每个角色的**规范化提示词、问题→解决方案手册、跨 harness 适配约定**见
[doc/design/agent-teams.md](doc/design/agent-teams.md)——该文是唯一事实源，各 harness 只做适配层。
